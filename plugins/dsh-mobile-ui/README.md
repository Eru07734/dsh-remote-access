# dsh-mobile-ui

**让 DSH 的设置面板在手机 / 平板上能用。** 只注入一段 CSS，桌面渲染完全不动。

拿手机或平板访问宿主机 GUI 的人读这一页 —— 尤其是发现"设置项每行只剩一个字"的时候。

## 它补的缺口：设置面板是写死的桌面双栏

设置对话框出厂就是固定双栏。在 412×915 的手机视口下（headless Edge + CDP 量测）实测：

```
[role=dialog][aria-modal]   364x800 at (24,58)   flex-direction: row
  ├── nav                   188px 宽（分区列表）
  └── div（内容）            176px 宽  ← 头部 + 一个 2023px 高的选项面板，塞在 738px 里滚动
```

内容区只有 176px，于是每个标签都折成一行一个字，并且有 **32 个元素**溢出视口底部 —— 设置基本没法读。

## 它做什么

往 webserver 的结构化注入表里推一行 `kind: 'style'`（第一方插件用的是同一个机制：
`dsh-host-webserver` 的 `renderRow` 把 `kind: 'style'` 变成 `<head>` 里的 `<style>`）。
CSS 整体包在 `@media (max-width: 820px)` 里，**大于 820px 的桌面渲染一个像素都不变**。

选择器是**结构式**的，这是刻意的：出厂 class 名是构建哈希（例如 `VOzbGW_nav`），每次前端重建都会变；
而 `[role="dialog"][aria-modal="true"]` → `nav` + 内容子节点这个结构，才是这套布局真正依赖的契约。

| 项 | 值 |
|---|---|
| 通道 | plain（绝对路径挂载） |
| `inject` | `['webServer']` |
| 接缝 | `ctx.on('webserver/index-inject')` |

## 修好之后（同一次测量，前后对比）

| | 修前 | 修后 |
|---|---|---|
| 对话框 | 364×800 @ (24,58) | **412×915 @ (0,0)**（满屏） |
| 分区列表 | 188px 竖排 | **412px 横向标签条**（高 102） |
| 内容区宽 | 176px | **412px** |
| 溢出元素 | 32 个 | **0 个** |

手机上**重新加载页面**即可生效（样式是服务端注入进 HTML 的，已经打开的页面不会自动变）。

## 单独装 / 单独关

- 装：`config/install.ps1 -Apply` 会一起装；只想装这一个，就把 `config/fragments/01-lan-access.patch.yml` 里那条 `id: mobile-ui` 的 insert 追加进 profile 补丁。
- 关：删掉那条 insert 即恢复出厂布局。

## 怎么验证

用任意 CDP 客户端（或浏览器的设备模拟）把视口设成 412×915，打开设置面板：
对话框应当铺满视口、分区列表变成顶部横向标签条、内容区占满剩余宽度。
